# Joi Changelog

## Unreleased

- Stopped the Joi Web deploy from being able to reset the box onto a tree that cannot run it. `deploy-joi.sh` moves the checkout with `git reset --hard "origin/$BRANCH"` and `BRANCH` defaults to `main` — a branch that predates the web experience and carries no broker at all. The reset succeeds, the seed step fails, and the box is left on a Core that does not understand one argument the broker passes it; the site keeps rendering, so nobody finds out until a visitor cannot open a session. The target now answers for itself before anything is written, and not by whether the branch name looks right, which is what the person typing it already believed: the two contracts that have to hold after the reset — this box's systemd unit against the target's broker, and the target's broker against the target's Core — are read out of the target itself and compared flag by flag, so no hand-written list goes stale the first time someone adds one. A target too old to carry the checker fails at the first step, which is the same answer by a shorter route. The repository is checked against its own guard in CI, so a broker flag added without the matching Core flag fails there rather than on the box.

- Gave a web visitor's realtime call back the two things it was missing: an answer in the language they spoke, and a voice. Both came from the same shape of mistake — a rule that was right on the desktop and was never re-read against a guest. The chat language ships as "follow", which is a setting meaning "whatever the user just said" and not a language, and it was handed to the caption rewrite verbatim: the text model was asked to write the line in a language named "follow", picked English, and a visitor who spoke Chinese read English back. "follow" is now resolved against that turn's own transcription before anything is asked of a model, and a visitor speaking the character's own language needs no rewrite at all — the spoken line is already the line they read. Separately, realtime would only speak through GPT-SoVITS. On a desktop the character voice and GPT-SoVITS are usually the same thing so nothing showed; a web visitor's character voice is a cloud voice, so every turn produced captions and silence and said only that a local component the visitor never had was not ready. Realtime now speaks in whatever voice this Joi already speaks in and still refuses the provider's own audio and any system voice, the consent screen names the route the machine actually has — a cloud voice means the reply text is sent to that provider too — and a turn that produces no samples reports itself muted instead of leaving the window waiting for a sound.

- Added the anonymous Joi Web experience without forking the Shell or turning Core into a shared multi-tenant process. A browser platform adapter preserves the Tauri path; full and compact iframes share one isolated Core and its existing broadcasts; guest UI exposes only chat, characters and read-only memory. A loopback broker creates clean per-visitor workspaces, allocates WS/asset port pairs, dynamically proxies both paths and reaps them by TTL. Core now validates browser origins, builds public asset URLs, projects a guest-safe ready payload and enforces the public RPC allowlist after authentication and before dispatch—the Caddy template intentionally handles TLS only because it cannot whitelist JSON-RPC methods inside WebSocket frames. Paid calls reserve and settle per-session and shared daily token budgets at the model-call funnel; realtime voice has single-owner, per-call, per-visitor and shared daily server limits with a Core-owned stop timer. The repository also includes the embed — one iframe that changes size rather than two that duplicate the session — plus the clean-seed generator, guest config, systemd/Caddy templates, and local end-to-end coverage.
- Connected the curated JoiDebug Web library with exactly four roles: Hiyori Live2D, AvatarSample_A VRM with all ten VRMA files and voice references, the Miku MMD/VMD test package, and the Cat girl tachie package. The seed excludes 星野澪 and Seed-san without copying character runtime or memory, records forbidden transcription tooling instead of silently discarding it, and keeps every declarative asset byte-exact. Character list/ready projections now publish session-scoped model, motion, sprite and expression URLs instead of local paths or multi-megabyte inline images; Live2D runtime paths respect `/joi-shell/`, and cross-origin tachie artwork can produce safe canvas thumbnails.
- Stopped OCR calling itself ready when it could only read some of the languages it was configured for. Tesseract complains about a language it cannot load, carries on with the ones it can, and exits 0 — so through pytesseract a machine with only English data returned a successful reading of a Chinese screen with most of the words absent, and the runtime reported OCR ready throughout. Readiness now means the configured languages are installed, and the advice says which piece is missing instead of telling someone to install dependencies they already have. A language list that cannot be read is not treated as evidence of a missing language: failing there would be a worse error than the quiet degradation this exists to catch.
- Gave a release build the capabilities the development environment already had. Pillow sat in the optional OCR requirements, which no release installed, while `vision/mac.py` imports it at module scope and `vision/windows.py` grabs through it — so a signed build reported its screen observer unavailable and meant it, on both platforms. The macOS display geometry package was installed by no release either, which leaves the layout untrusted and makes Computer Use refuse to derive a click point. Capture is a core dependency now rather than an OCR extra, the macOS release installs its platform package, and every lane ships the OCR wrapper so that installing Tesseract is all a user needs — the executable stays a system dependency pip cannot supply, and OCR still reports itself unavailable until it is there. All three are permissively licensed and were already in the notices. `packaging_smoke` fails if any of it stops shipping, reading the install line rather than any mention of it: the first version of that check passed a workflow that had stopped installing the package, because a comment naming the file looks the same to a substring search.
- Let a deletion reach the copy taken before the SQLite migration. `events.jsonl.pre-sqlite-backup` is the same stream in another file, so a deletion that reached the live log and stopped there left the same conversation readable beside it.
- Sorted `docs/KNOWN_ISSUES.md` into what is open, what has never run on real hardware, and what is a deliberate boundary. One list was carrying all three, which made a fail-closed design read like an unfixed bug and buried the four entries that are actually open.
- Stopped Codex runs accumulating, and let a deleted conversation take its own with it. Every run left three files — the event log, the error output and the final summary — and nothing ever removed them: roughly 1500 runs and 11MB on a development machine, all of it still holding the goal text and the model's answer, including for conversations the user had since deleted. The directory keeps a recent window now, dropping a run whole rather than in pieces, because a summary whose event log is gone reads as a broken card rather than an expired one. A confirmed deletion reaches the files as well: the run itself carries no conversation, but the card that names it does, so the paths are read out of the events before the rows holding them go. Those paths come out of stored payloads and name files to delete, so each is resolved and required to be inside the run directory first.
- Stopped the Core regression suite writing into the data directory of whoever ran it. `run_agent_companion_tests.py` used the checkout as its workspace, so each of the ~30 app instances it builds wrote real events, audit records and SQLite rows into `data/agent_companion/` — which is how the local event log reached 90MB, and which meant the command AGENTS.md documents was never safe to run against an install whose data mattered. The checkout and the workspace are separate names now, the latter a throwaway seeded with the same built-ins an installed build gets. `tools/p4_closeout_report.py` resolved its report against its own location, so it wrote there from a subprocess whatever it was told; it takes `--root` now.
- Remembered where the desktop companion was left. The compact window came back to wherever the shell happened to put it, so parking her in a corner lasted until the next launch. Her resting position is kept now -- the position she settles at, not every frame of the drag -- and it is only restored when enough of her would land on a screen that still exists, because a window restored onto an unplugged monitor cannot be dragged back. Moving the window from code, which is how leaving compact mode hands the main window its own position back, is never mistaken for the user placing her.
- Made compact mode the same app in less space. It offered a text field and click-to-record and nothing else, so starting a realtime call, watching together, attaching a file or reaching memory and settings all meant leaving it first — and the character was a fixed box, so the one thing a desktop companion is expected to do, be the size you want in the corner you put her in, was not offered at all. The wheel now scales her between 0.6x and 2x and the window grows with her rather than clipping her; the scale is kept, because a size someone set deliberately should survive a relaunch. Reading the wheel's direction rather than its magnitude is what keeps one notch feeling the same on a trackpad and a mouse. Everything the composer's quick menu starts is reachable from the compact dashboard, and the two that need a readable window — memory and settings, and the attachment picker whose chip list lives in the chat section — restore it first instead of drawing a full cabin into a 360px pet. Borrowed from AIRI's desktop window, which gives the model its own scale beside the window's and remembers where it sits.
- Stopped the compact control panel from lying across her legs. The window reserved 90px for a panel that is 166px tall and sits 16px off the bottom, so the two overlapped by 92px — and adding the quick actions to that panel would have made it worse. The reserve is measured now, and a test holds it, because the number is only correct until someone adds another row.
- Made a deleted conversation actually gone, and stopped the compatibility log from growing without end. Deleting a thread removed it from the database and from the window while `events.jsonl` kept every display card and voice line it had ever carried, so a confirmed deletion meant hidden rather than deleted — and the log had reached 90MB on a development machine although nothing reads further back than its last few hundred lines. A confirmed deletion now reaches the log as well, including the threads a deleted project takes with it and rows old enough to carry only a thread id; the log keeps a bounded tail instead of every event ever written; and a purge that removes the newest rows leaves a marker behind, so a restart cannot hand a fresh event a sequence number a surviving row already holds. The bound is bytes as well as rows, because a cap counted only in rows leaves a log of tool results sitting above its own trigger and rewriting itself on every event.
- Closed three gates that were not gating. The 94 Shell tests never ran in CI — the required macOS lane type-checked and built the Shell but never tested it; CI ran Node 20 while the Shell test runner needs 22 and the bridge's packaging step refuses anything lower; and the Minecraft bridge was only syntax-checked, never built, so its offline smoke never ran and a release package shipped with a game adapter that could never start — fail-closed, so it reported itself unavailable rather than misbehaving, but silently absent. All three lanes now build the bridge and run what they claimed to. `docs/RELEASE_READINESS_2026-08-18.md` records what the 1.0 mainline still needs, with the command behind each claim.
- Made the documents usable as judges again. The roadmap said thirteen primitives and the realtime notes said ten while the contract carried twenty-four; the TDD mentioned Minecraft once, in a syntax-check command, and had no design section for a capability with its own process, its own approvals and its own privacy projection. The counts are correct now, the TDD carries the adapter's actual boundaries, and known issues records what has never run against a real world rather than leaving offline coverage to read as proof.
- Measured the realtime voice path instead of guessing at it. Nothing on it was timed, so every explanation for a slow answer — the provider, the local voice, the microphone — was a hypothesis with no way to settle it. Each spoken turn now records four marks: the provider's silence detection, its first text, its finished answer, and the moment the local voice hands over its first audio chunk. Developer mode shows that turn's breakdown and the call's running P50/P95 of silence-to-audio. It is whole milliseconds and a turn count — no text, no ids, no provider detail — and a failure to record can never interrupt the voice.
- Gave the slice its acceptance evidence a shape. Twelve actions were added and nothing noticed the evidence had not moved: the offline smoke still reported "primitives=13" — coverage it no longer had — and only the original ten primitives have ever run against a real world. The smoke now exercises all 22 actions the bridge executes plus the block-budget ceiling, `docs/MINECRAFT_REAL_SERVER_WALKTHROUGH.md` breaks the slice's stated acceptance into 18 checkable scenes, and a recorder writes sanitized results locally — refusing any note that looks like a coordinate or an address, because the walkthrough runs in the user's own world. A test keeps all three in step.
- Grew the stage from three formats to six, and gave the character library something to show. MMD (PMX/PMD) and tachie now render; Spine is named in the vocabulary but refused at validation, because its runtimes are proprietary and need their own licence — a package that declares it is told why rather than failing at mount. The emotion table moved out of the Live2D module into a stage contract every renderer shares, so adding a format no longer means depending on an unrelated one. Importing now reports whether a package will *work* beside whether it can be *trusted*: macOS resource forks, basename collisions and legacy-codepage filenames are named instead of looking like renderer bugs, and a Live2D character shared as a bare .moc3 gets inferred settings rather than a refusal. Packages with no artwork get a thumbnail drawn by the renderer that would draw the model.
- Reserved all rights, and stopped presenting Live2D's character as ours. The repository was public with no LICENCE — all rights reserved by default, and silently so. The default Live2D model turned out to be Live2D's own sample character Hiyori Momose, renamed to `joi.moc3` and labelled `asset_policy: original` under an invented name; her terms allow free use at this scale but require the copyright notice, forbid design changes, and forbid presenting her as the publisher's own creation. The assistant is Joi and the model is Hiyori now, which is the same separation AIRI makes. One near-miss on the way: the ignore rule named a single model's directory, so renaming it made the licensed artwork committable to a public repository — it ignores the whole directory now.
- Generated the third-party notices instead of maintaining them by hand. The old list had 18 entries and said so itself; the artifact actually carries 611 across npm, Python and Rust. Generated lists can also be wrong in the other direction: PySide6 is declared in `requirements.txt` but excluded from the frozen sidecar, so listing the installed environment would have claimed a release ships LGPL/GPL Qt that it does not. The generator reads the build's own exclusions rather than restating them, and `--check` fails a release whose notices have drifted.
- Charged the route to the block budget it actually spends. Opening the pathfinder to break and place blocks bounded *which* blocks and *where*, but not *how many*: the budget reserved only what an action set out to change — ten for `mine 10`, nothing at all for walking — so a route that tunnelled through a mountain to reach the work spent none of the ceiling the user confirmed, and the receipt reported none of it either. Every block this bot breaks or places is now counted, whoever asked for it; the receipt reports that number, the session budget is settled against it rather than against the estimate, and each goal is handed what is left of the ceiling so it stops itself at the block that would cross it — instead of Core learning from the receipt that it already had.
- Closed the capability gap against Numen. Joi could mine, craft and carry, but could not smelt, tidy loot away, equip, drop, fish or sleep — and, worse, could not *look anything up*: no recipe lookup, no reading a chest without emptying it, no sense of which way a village lies. Ten actions were added, and the read-only ones are what stop the model guessing. Each keeps the boundaries the rest already had: storage needs the container permission, smelting and dropping stay inside the allowed blocks, every action still costs one of the confirmed budget, and lookups answer in words — "village 在north方向，far" — because a bearing and a distance band are the only shape a coordinate cannot hide in.
- Let the route bridge, pillar and tunnel — with the user's own allow-list. The pathfinder was locked flat (`canDig = false`, no scaffolding), so Joi could not cross a one-block gap; opened wide it would carve through someone's base. It may now break and place, but only the blocks mining and building were already approved for, only inside the confirmed radius, and only when the scope grants building.
- Made a running plan visible. Approving one used to be the last thing the user saw until it finished or failed; each step now reports into the conversation where it was approved.
- Gave Joi a place to be taught. Markdown notes in `config/minecraft-skills/` — base conventions, mod rules, anything that lives in no data structure — are indexed into her prompt by name and loaded only when she asks for one. Deliberately not the Skill system: that installs and sandboxes *code*, with digests and provenance because a script can do anything; these are prose, never executed, and a note name can never be a path.
- Made her remember the furnace she already has. World memory now carries the workstations a world contains, so she walks back to the crafting table instead of proposing to build another.
- Gave Joi eyes. She could read her own health and her own bag but had no idea what was in front of her, so "去采点橡木" was a guess and she had nothing concrete to be constructive about. The observation now carries what is around her as name + count + bearing + distance band — egocentric by construction, which is both how a companion would actually say it and the only shape that keeps absolute coordinates inside the bridge child, as every other observation field already does. (Design borrowed from Numen's egocentric semantic grid; no code taken — Numen's core is LGPL-3.0.)
- Stopped a cold bridge start from reading as a connect failure. Waiting for the Node child to spawn and load mineflayer shared the 1.5s budget meant for a control round-trip, so a busy machine reported `minecraft_bridge_ack_timeout` on connect.
- Stopped a brief network stall from ending a realtime call. The send queue holds under a second of speech, and any moment the provider socket did not drain used to be reported as a lost transport and terminate the session. Live audio is lossy by nature: the oldest frames are now dropped instead, and only a sender that has stopped draining entirely still counts as gone.
- Made the audio sequence self-heal. The Shell counted every frame it handed over while Core only counted the ones it accepted, so a single rejected frame desynchronized the two permanently and every later frame was refused — the call stayed "listening" and Joi never heard another word. A forward skip now resynchronizes; a repeat or a rewind is still refused.
- Gave a dropped realtime call one silent re-dial instead of leaving the user to press the button again. Only transport faults retry, only once per call, and stopping cancels a pending retry.
- Gave Joi a body that reads as inhabited. Nothing in the bridge ever called `look()`, so she stood with her head locked at whatever pitch she spawned with and never moved between goals. She now meets the player's eyes, glances around when alone, and has sparse idle beats — a jump, a step. It is not a goal: it changes no blocks, spends no action budget, writes no receipt, yields the moment real work starts, and stays inside the confirmed radius.
- Stopped a slow Minecraft task from ending the whole session. On a goal timeout the bridge child called `bot.quit()` and `process.exit()`, so "帮我去挖足够的橡木，然后建造工作台" — a task that simply takes minutes — disconnected Joi from the world and took the realtime voice call down with it, every time. A long task now stops the work and keeps the world; the child owns the action deadline (5 minutes by default, up from 2) and Core's ack window is derived to always outlive it, so Core never cancels a goal the bot is still succeeding at. Core also no longer terminates a healthy bridge when its own backstop fires — it cancels that goal instead, which keeps the "no effects after a reported failure" guarantee without killing the session.
- Made Joi able to follow the user. The scope check compared player names case-sensitively while the in-game chat gate beside it compared casefolded, so the same permission disagreed with itself; and the model was never told any player name, so "跟着我" produced an invented one that was then refused as out of scope. Names now match case-insensitively, the instructions say who the user is in-game, and `player` is optional — with one confirmed player Core fills it in rather than letting the model guess.
- Stopped proactive Minecraft lines from coming out in the wrong language. Autonomy writes straight into the chat and the character voice and had no language rule anywhere in its prompt or downstream of it, so a Japanese-named character answered a Chinese session in Japanese.
- Gave Joi something to be constructive with. The observation carried only how many inventory slots were full, never what was in them, so she could not tell she was already holding the oak she had just mined. Item names now reach her, along with who she may follow, and the prompt asks for useful work instead of ending on "output none when unsure".
- Let Joi talk while she works. A goal in flight ended the autonomy tick outright, so she went completely silent for the whole minutes-long task she was in the middle of. She can now narrate it — she just cannot start a second action — and the default beat between lines is 20s rather than 30s.
- Taught crafting to make what it is missing. A crafting table needs planks, so carrying only logs meant no recipe was craftable and Joi reported `recipe_not_found` while holding the wood for it. Ingredient chains now resolve to a bounded depth.
- Gave the voice a way to answer a multi-step goal. Only one action was allowed per turn, so "mine enough oak, then build a crafting table" got one action and a report that the whole request was done. A `minecraft_plan` proposal now compiles the user's own words into a step plan and puts it on the same confirmation card a typed goal produces.
- Told the truth in the realtime microphone disclosure about reading the game screen. It promised the frame "只在本机做文字识别" and that "原图不会上传", which holds only without a vision model — with one configured, the frame itself is sent to it for the scene summary, which is the normal setup. Core now reports which of the two is running and consent describes that, including how to turn the upload off.
- Answered every refused realtime tool call instead of leaving the turn silent. A provider that proposed two things at once ("挥个手，然后帮我打开 Chrome") received no output for either, so both calls stayed open, no response followed, and Joi said nothing at all — including when Scheme A refused an unauthorized attack, where she could not say why. Every call is answered now, refusal included, with one response for the batch so she says it once.
- Stopped a running Minecraft plan when its session stops. The plan loop kept stepping into a world that was gone; each submit failed closed, so nothing reached the world, but the plan only found out by failing a step instead of being told to stop.
- Bounded the per-session bookkeeping both slices accumulate. A finished Minecraft session used to leave its goals — each holding a full result payload with a session snapshot and a receipt — its plans and its chat throttle in memory for as long as Core ran, and a session with autonomy running grew them the whole time; a long realtime call kept every call id it had ever seen. Receipts and world memory remain the durable record.

- Stopped a Minecraft request from launching a different game. "帮我在 Minecraft 里挖点石头" matched the OK-WW branch of the planner, so a Wuthering Waves automation skill answered for Minecraft. Minecraft is now routed before the planner — which can only name tools in the registry, while the game lives behind its own bridge, confirmed scope and receipts — and the goal is compiled into a step plan shown for approval in the conversation, answerable from that one card. Refused, ambiguous and stale proposals report as such rather than being narrated as done, and the microphone disclosure now says so before the session opens.
