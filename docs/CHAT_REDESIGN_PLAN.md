# 对话界面重塑方案

状态：待确认。本文只提方案，不含实现。

## 1. 现在的问题

不是"不好看"，是**信息层级反了**：一轮对话里，角色说的话最小，系统状态最大。

以实际截图为证，「帮我打开b站」那一轮里屏幕上共有 4 块内容：

| 内容 | 高度占比 | 是用户想看的吗 |
|---|---|---|
| 角色回复「桌面自动操作 当前不可用。」 | ~1 行 | 是 |
| 带边框的状态卡「没有完成 10:28」 | ~3 行 | 出问题时才是 |
| 「这轮任务没有跑通，可以展开执行过程查看细节。」 | ~2 行 | 几乎不是 |
| 「重试这条请求」按钮 | ~2 行 | 出问题时才是 |

结果是**状态装饰的高度是回复本身的 7 倍**。两轮失败叠在一起，整屏看不到一句人话。

具体毛病，逐条对应 GPT / Claude 的做法：

| 现状 | GPT / Claude 的惯例 |
|---|---|
| 每轮工具调用都生成一个**带边框的卡片** | 状态是一行内联文字，不成卡 |
| 每条助手消息都重复「头像 + 角色名」 | 连续同一说话人不重复署名 |
| 每条用户消息都带「你」标签 | 用户消息右对齐即可，不署名 |
| 每张卡都带时间戳 | 时间悬停或分组显示 |
| 「2 个动作已记录 / 最近：computer.workflow」直接暴露在对话里 | 内部标识不进主界面 |
| 能力会话卡常驻占位，会话结束后仍在 | 运行态控件不占对话空间 |

最后一条我已经按你的要求删掉了。

## 2. 必须守住的约束（来自本项目自己的文档）

重塑不能变成"把卡片都删掉"，因为 PRD/TDD 明确要求其中一部分存在：

- **PRD §9.1**：「审批卡与普通消息视觉分离」——审批**必须**在视觉上区别于普通消息。
- **TDD §910**：「审批卡不可遮挡」——acting 动效不能盖住 waiting/paused/failed。
- **PRD §120**：「角色即信任界面：表情、语音、任务卡和审批必须表达真实系统状态」——任务卡不能为了好看而说谎或消失。
- **PRD §9.1**：「开发者事件、原始标识、审计细节和运行时诊断**仅在 Developer Mode 展示**」——`computer.workflow`、receipt 计数这类内容本就不该在对话里。
- **PRD §9.1**：能力会话控制属于 **Workspace**，对话区只负责「普通对话、项目协作和运行结果」。

**结论**：要压缩的是"例行状态"，要保留甚至加强的是"审批"和"失败"。这两类不是同一种东西，现在却长成同一张卡。

## 3. 目标结构

一轮对话从 4 块降到 **1~2 块**：

```
你                                          帮我打开b站
────────────────────────────────────────────────────────
[头像] AvatarSample_A
       我来打开，需要你确认一下。
       ⟳ 正在打开浏览器 · 展开                 ← 一行内联，不是卡
```

三种状态，三种待遇：

**A. 顺利完成 —— 降级为一行**
回复正文照常，下面一行浅色小字：`✓ 已完成 · 3 步 · 展开`。点开才出现步骤列表。默认不占空间。

**B. 需要审批 —— 升级，保持独立卡片**
这是 PRD 要求视觉分离的唯一一类。保留边框、保留强调色，但移到角色消息的正下方并**紧贴**，让「谁在要权限」一眼可读。按钮文案维持「允许并继续 / 停在这里」。

**C. 失败 —— 中等**
一行状态 + 一句人话原因 + 一个「重试」文字按钮（不是当前的大按钮块）。原因要说人话：这次「桌面自动操作 当前不可用」其实是幂等键撞了三天前的记录，用户根本无从判断——**错误文案本身要跟着改**（这一条我已经在 Core 侧修了，前端只需要照实显示）。

## 4. 消息本体的调整

- **连续同一说话人不重复署名**：一轮里角色只在第一条显示头像+名字。
- **用户消息不显示「你」**：右对齐 + 气泡即可。
- **时间戳移出主流**：悬停显示，或每隔一段时间插一个日期分隔。
- **空状态保留**：现在的问候 + 三个引导按钮是对的，GPT/Claude 也是这个思路。

## 5. 分阶段实施

按"先止血、再重构"的顺序，每步都可独立验证、独立回滚：

| 阶段 | 内容 | 风险 |
|---|---|---|
| P1 | 例行成功状态由卡片降为一行内联；步骤列表默认收起 | 低。只动 `execution-rail` 的渲染分支 |
| P2 | 失败态压缩为「一行 + 原因 + 文字重试」 | 低 |
| P3 | 审批卡独立出来，紧贴角色消息，保持视觉分离 | **中**。要确保任何情况下都不被遮挡（TDD 910），需要真机点一遍 |
| P4 | 署名/时间戳/连续消息合并 | 低 |
| P5 | 能力会话控制迁到 Workspace（暂停/接管/取消） | **中**。这是安全控件，迁移前不能有真空期 |

**P5 是有依赖的**：我这次已经把那张卡从对话里删了，所以「暂停 / 我来接管 / 取消」现在在界面上没有入口。运行中的自动化仍可用其他方式停（关窗口、取消审批），但少了一个显式的停止按钮。这是个需要尽快补的缺口，建议 P5 提前到 P1 之前做，或者至少和 P1 并行。

## 6. 需要你拍板的三件事

1. **P5 提前吗？** 我倾向提前——少一个显式停止按钮，对一个会操作你电脑的产品来说不是小事。
2. **步骤列表默认全收起，还是失败时自动展开？** 我倾向失败时自动展开，成功时收起。
3. **时间戳**：悬停显示，还是每 N 分钟一个分隔线？GPT 用后者，Claude 基本不显示。

## 7. 不做什么

- 不引入新的 UI 框架或组件库。
- 不改 `AgentEvent` 协议——这是纯呈现层的重排，Core 不动。
- 不隐藏审批、失败或风险信息。压缩的是**例行成功**的噪音，不是可审计性。
